VERSION: v1.2
DATUM: 2026-01-21
STATUS: ACTIVE
PRIORITY: MUST
REQUIRES: B050, B060, B150, B200, docs/nft_service_ip_scopes.txt
INFLUENCES: B230, B240, B270
OWNER-INTENT: Panel/Portal/Blockpage auf SERVICE_WEB (10.77.0.3 / fd77:0:0:0::3) im SERVICE_NET, niemals WAN.
OWNER: Marco (Owner) + ChatGPT (Co-Architect)

NOTES:
- Webstack ist strikt intern (Service-IP/VPN) und nie WAN-exposed; DB-Tools (phpMyAdmin) sind admin-only.
- Kein „Feature-Creep“: nur das, was Panel/Portal braucht; alles andere ist out-of-scope.
- Härtung ist Pflicht: RateLimits, sichere Cookies, minimale PHP-Exposure, klare getrennte vhosts/scopes.
================================================================================

1) ZWECK
- OpenResty als Frontend für:
  - Panel (PHP via PHP-FPM)
  - /diag endpoint
  - Blockpage (HTTP + TLS intercept logic in B230)

2) GRENZEN
- Kein Apache.
- Keine Webports auf WAN.
- phpMyAdmin admin-only.

3) ABHÄNGIGKEITEN
- Requires: B050, B060, B150, B200, docs/nft_service_ip_scopes.txt
- Influences: B230, B240, B270

4) INPUTS
- Bind: SERVICE_WEB (10.77.0.3 / fd77:0:0:0::3):80/443
- PHP-FPM local socket/localhost
- DB local (MySQL/MariaDB)

5) OUTPUTS
- User accessible: panel/status/portal/diag (as per firewall)
- Admin accessible additionally: phpMyAdmin (separate vhost/path + firewall)

6) MUST
- OpenResty only listens on SERVICE_WEB (10.77.0.3 / fd77:0:0:0::3) (kein 0.0.0.0, kein WAN-bind)
- firewall/vhost-scope definiert user/admin access: user/restricted dürfen niemals phpMyAdmin erreichen; admin-only Source-IP ist ADMIN_VPN_NET 10.77.2.0/24 (gemäß docs/nft_service_ip_scopes.txt)
- TLS for panel (trusted via CA import)

7) OPTIONAL
- Separate server blocks for:
  - vpn.status (panel)
  - blockpage host (wildcard) for MITM

8) FEHLERBILDER
- User can reach phpMyAdmin -> firewall/vhost wrong
- Web reachable from WAN -> bind/firewall wrong (SERVICE_WEB 10.77.0.3 darf nie WAN-exposed sein)

9) TESTS
- From WAN: cannot connect to SERVICE_WEB (10.77.0.3 / fd77:0:0:0::3):80/443 (SERVICE_WEB ist nie WAN-exposed; Bind+Firewall müssen das erzwingen).
- From user (LEGACY/MODERN, nicht restricted): can open panel/portal/diag on SERVICE_WEB (10.77.0.3 / fd77:0:0:0::3) only; cannot access admin tools.
- From admin (ADMIN_VPN_NET 10.77.2.0/24): can open admin tools zusätzlich, aber weiterhin nur intern via SERVICE_WEB (10.77.0.3 / fd77:0:0:0::3).
