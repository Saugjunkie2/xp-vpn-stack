BLOCK-ID: B230
TITLE: HTTPS Blockpage (MITM) / CA / On-the-fly Certs / RateLimit
VERSION: v1.1
DATUM: 2026-01-20
STATUS: ACTIVE
PRIORITY: MUST
REQUIRES: B060, B200, B220, B250, B260, docs/nft_service_ip_scopes.txt
INFLUENCES: alle
OWNER-INTENT: HTTPS Blockpage ohne Warnungen auf XP/MyPal.
OWNER: Marco (Owner) + ChatGPT (Co-Architect)

NOTES:
- HTTPS-Blockpage/MITM ist nur für Blocklisten-Ziele gedacht (Custom IP → interne Blockpage), nicht für generelles MITM.
- Ohne installierte interne Root-CA auf dem Client darf diese Funktion nicht als „funktioniert“ gelten.
- Zertifikats-Generierung muss gecached/gerate-limited sein, sonst wird der Server bei vielen Requests zum DoS-Ziel.
================================================================================

1) ZWECK
- Wenn AdGuard blockt:
  - AdGuard "Blocking mode: Custom IP" antwortet SERVICE_WEB 10.77.0.3 (nicht 10.77.0.1)
  - HTTP + HTTPS landen auf interner Sperrseite (SERVICE_WEB 10.77.0.3:80/443)
- HTTPS soll ohne Warnung funktionieren (Legacy-Target XP/MyPal):
  - interne Root-CA ist vertrauenswürdig im Client
    - Windows Trust Store (OS)
    - MyPal NSS Store (Browser)
  - OpenResty erzeugt leaf cert pro Host (SNI/Host) und cached diese (SNI/Host -> cert)
  - Ziel ist „no warning“ primär für MyPal (SNI-fähig) + typische Browser-Requests

2) GRENZEN
- Nicht 100% gegen Pinning/HSTS-Edgecases garantierbar.
- Apps/Clients mit Certificate Pinning können scheitern (akzeptierte Limitation; kein generelles MITM).
- Legacy/SNI:
  - „No warning“ ist primär für MyPal/Browser gedacht (SNI-fähig).
  - HTTPS-Clients ohne SNI können keine host-spezifische Zertauswahl erzwingen -> können Warnungen sehen (akzeptierte Limitation).
- Nur Blocklisten-Ziele: MITM/Blockpage ist strikt auf AdGuard-Blockfälle (Custom IP -> SERVICE_WEB 10.77.0.3) begrenzt, nicht als genereller Proxy/MITM missbrauchbar.

3) ABHÄNGIGKEITEN
- Requires: B060, B200, B220, B250, B260, docs/nft_service_ip_scopes.txt
- Influences: UX, support, B150 (Restricted Allowlist muss SERVICE_WEB:443 zulassen)

4) INPUTS
- Root-CA (offline storage optional; operational policy)
- Signing mechanism (on-box, intermediate possible)
- Rate limit rules (per client IP/host)
- Cert cache (SNI->cert)

5) OUTPUTS
- Blockpage served on HTTP and HTTPS for blocked domains (SERVICE_WEB 10.77.0.3:80/443)
- Minimal info:
  - "blocked" + reason-code (ohne interne Details/PII)
  - optional: "allowlist request" Hinweistext (ohne Kontakt-/Admin-Infos, die Enumeration erleichtern)
- Keine Admin-Funktionen/Endpoints auf der Blockpage-Route (Scope-Trennung ist Pflicht; admin-only bleibt admin-only).

6) MUST (wenn aktiv)
- Service-Bindings (SoT):
  - Blockpage/HTTPS läuft ausschließlich auf SERVICE_WEB 10.77.0.3:80/443 (kein 10.77.0.1, kein WAN-bind).
  - AdGuard Blocking mode: Custom IP zeigt auf SERVICE_WEB 10.77.0.3.
- Trust:
  - MyPal NSS import muss erfolgreich sein, sonst gilt "no warning" als nicht erfüllt.
- Caching + RateLimit:
  - Zert-Erzeugung muss gecached sein (Host/SNI -> cert; TTL/Eviction definiert), sonst CPU DoS.
  - RateLimit pro client_ip + host (sonst Subdomain-Flood kann Cert-Farm auslösen).
- Scope/Exposure:
  - Blockpage-Web darf keine Admin-Funktionen/Tools exponieren (admin-only bleibt ausschließlich ADMIN_VPN_NET 10.77.2.0/24 gemäß docs/nft_service_ip_scopes.txt).

7) OPTIONAL
- Custom IP block mode for AdGuard (primary)
- Additional captive portal integration

8) FEHLERBILDER
- Zertwarnung in MyPal -> NSS import failed or wrong profile.
- High CPU load -> rate limit/caching missing.
- Some domains still fail -> pinning/HSTS; acceptable limitation.

9) TESTS
- Blocked domain:
  - AdGuard liefert Custom IP = 10.77.0.3
  - HTTPS öffnet Blockpage auf SERVICE_WEB 10.77.0.3 ohne Warnung auf MyPal (NSS Trust vorhanden).
- Negative:
  - Ohne NSS-Import muss ein Warnzustand sichtbar sein (zeigt, dass Trust wirklich Voraussetzung ist).
- Flood/DoS-Resistenz:
  - Subdomain-Flood (viele Hostnames) erzeugt keine unbounded CPU/Load (RateLimit+Cache greifen; Server bleibt responsive).
- Scope:
  - User/Restricted erreichen Blockpage (443) nur als Blocklisten-Ziel; keine Admin-Endpunkte erreichbar (Admin-Tools nur aus 10.77.2.0/24).
