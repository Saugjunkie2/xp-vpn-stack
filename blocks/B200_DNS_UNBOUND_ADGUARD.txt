TITLE: DNS Stack (Unbound + AdGuardHome)
VERSION: v1.5
DATUM: 2026-01-21
STATUS: ACTIVE
PRIORITY: SHOULD
REQUIRES: B060, B150, B220, docs/nft_service_ip_scopes.txt
INFLUENCES: B210, B220, B230, B240
OWNER-INTENT: Sauberer Resolver + Filter + interne rewrites.
OWNER: Marco (Owner) + ChatGPT (Co-Architect)

NOTES:
- DNS-Stack ist intern im SERVICE_NET: AdGuardHome DNS bindet auf SERVICE_DNS 10.77.0.1:53; Unbound läuft als server-only Upstream auf SERVICE_RESOLVER 10.77.0.2:53 (Clients dürfen Unbound nie direkt erreichen).
- Kein „User wählt DNS“: Clients sollen DNS nur über den Server nutzen (User-Netz darf nicht frei nach außen resolven).
- UI/Management (AdGuard UI etc.) ist admin-only; Firewall/Bindings müssen das erzwingen.
================================================================================

1) ZWECK
- Unbound als Resolver (server-only, SERVICE_RESOLVER 10.77.0.2:53; kein Client-Access)
- AdGuardHome als DNS-Frontend für Clients (SERVICE_DNS 10.77.0.1:53) + Blockpage-Routing auf SERVICE_WEB

2) GRENZEN
- AdGuard UI ist admin-only.

3) ABHÄNGIGKEITEN
- Requires: B060, B220, docs/nft_service_ip_scopes.txt
- Influences: B210, B230

4) INPUTS
- Unbound bind SERVICE_RESOLVER (10.77.0.2 / fd77:0:0:0::2):53 (UDP+TCP)
  - Scope: server-only (nur vom Host selbst + von SERVICE_D...1 erreichbar; Clients dürfen 10.77.0.2:53 nie direkt erreichen).
- AdGuard bind SERVICE_DNS (10.77.0.1 / fd77:0:0:0::1):53 (UDP+TCP), UI (10.77.0.1 / fd77:0:0:0::1):2000 (admin-only)
- Upstream of AdGuard = Unbound (SERVICE_RESOLVER 10.77.0.2 / fd77:0:0:0::2 :53)
- Server-eigene DNS Queries (OUTPUT): nutzen Unbound direkt über 10.77.0.2:53 (z.B. resolv.conf -> 10.77.0.2), nicht DNAT (B210 DNAT gilt nur für Client-Traffic).

5) OUTPUTS
- DNS for user/admin
- Rewrite:
  - vpn.status -> SERVICE_WEB (10.77.0.3 / fd77:0:0:0::3)
- Blocking mode: Custom IP -> SERVICE_WEB (10.77.0.3 / fd77:0:0:0::3)

6) MUST (wenn aktiv)
- DNS (SERVICE_DNS 10.77.0.1 / fd77:0:0:0::1 :53, UDP+TCP) ist für User/Admin/Restricted erreichbar (Enforce via B210 DNAT v4+v6 + B150 + docs/nft_service_ip_scopes.txt input allowlist).
- AdGuard UI (SERVICE_DNS 10.77.0.1 / fd77:0:0:0::1 :2000) ist strikt admin-only (Source-IP in ADMIN_VPN_NET 10.77.2.0/24 gemäß docs/nft_service_ip_scopes.txt).
- Clients (User/Admin/Restricted) dürfen SERVICE_RESOLVER (10.77.0.2 / fd77:0:0:0::2 :53) NICHT direkt erreichen (Unbound ist server-only; nur AdGuard/Host darf upstream nutzen).

7) OPTIONAL
- Multiple profiles per group (user/admin)

8) FEHLERBILDER
- DNS fails -> check bindings and firewall.
- Blockpage not hit -> blocking mode wrong or web not reachable.

9) TESTS
- From client: resolve works (UDP) und TCP DNS fallback funktioniert ebenfalls (TCP/53).
- Blocked domain returns SERVICE_WEB (10.77.0.3 / fd77:0:0:0::3) (AdGuard "Custom IP" mode -> Blockpage/Portal).
- Restricted client: DNS funktioniert weiterhin (DNAT->SERVICE_DNS 10.77.0.1 / fd77:0:0:0::1 :53; input allowlist erlaubt 53).
- Negative Test: Client (User/Admin/Restricted) kann SERVICE_RESOLVER (10.77.0.2 / fd77:0:0:0::2 :53) NICHT direkt erreichen (MUSS failen).
- Admin (Source-IP in 10.77.2.0/24) can open UI (SERVICE_DNS 10.77.0.1 / fd77:0:0:0::1 :2000), user/restricted cannot.
