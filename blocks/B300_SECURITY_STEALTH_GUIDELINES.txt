TITLE: Security & Stealth Guidelines
VERSION: v1.2
DATUM: 2026-01-22
STATUS: ACTIVE
PRIORITY: MUST
REQUIRES: alle
INFLUENCES: alle
OWNER-INTENT: Leitlinien, damit Betrieb stabil und unauffällig bleibt.
OWNER: Marco (Owner) + ChatGPT (Co-Architect)

NOTES:
- Baseline-Härtung ist nicht optional: IPv6 Leak-Control (LEGACY v4-only; ADMIN/MODERN ggf. Dualstack), SSH eingeschränkt, minimal services, WAN ping optional/limitiert.
- Kein Overengineering (IDS/IPS etc.) in Baseline; Fokus ist robust + verständlich.
- Regelmäßige Updates/Backups + Log-Retention gegen Disk-Full sind Teil der Security (operational security).
================================================================================

1) ZWECK
- Definiert Sicherheits- und Exposure-Regeln.

2) GRENZEN
- Kein Adminzugang über WAN.
- User sind untrusted.

3) ABHÄNGIGKEITEN
- Requires: alle

4) RULES MUST
- WAN: nur UDP 500/4500 + ESP.
- SSH: bind nur SERVICE_SSH (10.77.0.5 / fd77:0:0:0::5); nft allow nur Admin-Netz (ADMIN_VPN_NET) (Zone-0 SERVICE).
- Web: bind nur SERVICE_WEB (10.77.0.3 / fd77:0:0:0::3); nft allow user/admin subsets.
- Alles andere: no WAN-binds.
- IPv6: Dual-Stack ist Standard für ADMIN+MODERN (v4+v6 gleichwertig: DNS-Zwang, Full-Tunnel, Policies). LEGACY bleibt IPv4-only. Leak-Control/WAN-Exposure bleibt strikt (keine WAN-binds; nur SERVICE_* + allowlists).

5) OPTIONAL
- ICMP rate-limit.
- Additional outbound blocks.

6) FEHLERBILDER
- Service exposed on WAN -> immediate incident.
- Abuse report -> check blocks + compromised admin credentials.

7) TESTS
- Regular external scan results documented.
- Internal access matrix validated.
