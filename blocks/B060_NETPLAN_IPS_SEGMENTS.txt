- LEGACY (XP/Vista) bleibt IPv4-only; ADMIN/MODERN sind Dualstack (IPv4+IPv6).

1) ZWECK
- Definiert das kanonische Netzmodell (Zonen/Segmente) inkl. Service-IPs als feste Anker für Firewall, DNS-Zwang, Panel und Ops.

2) SEGMENTE (SoT)
2.1 SERVICE (Infra-only, keine Client-Pool-IP)
- SERVICE_NET_v4: 10.77.0.0/28
- SERVICE_NET_v6: fd77:0:0:0::/64

Service-IPs (v4/v6):
- SERVICE_DNS:     10.77.0.1   / fd77:0:0:0::1    (AdGuard DNS + UI, UI später admin-only scoped)
- SERVICE_RESOLVER: 10.77.0.2  / fd77:0:0:0::2    (Unbound, server-only)
- SERVICE_WEB:     10.77.0.3   / fd77:0:0:0::3    (Panel/Portal/Blockpage + /diag)
- SERVICE_NTP:     10.77.0.4   / fd77:0:0:0::4    (NTP für XP-Zeitstabilität)
- SERVICE_SSH:     10.77.0.5   / fd77:0:0:0::5    (SSH, admin-only Scope; kein USER/RESTRICTED Zugriff)
- SERVICE_GW_PPP:  10.77.0.10  / fd77:0:0:0::10    (PPP peer/local gateway-Anchor für Legacy-PPP; kein Service-Port-Ziel)

2.2 LEGACY (XP/Vista, L2TP/IPsec)
- LEGACY_VPN_NET_v4 (Pool): 10.77.16.0/20
- LEGACY ist IPv4-only (kein IPv6 im Legacy-PPP Pool)

2.3 ADMIN (Dualstack, IKEv2)
- ADMIN_VPN_NET_v4 (Pool): 10.77.2.0/24
- ADMIN_VPN_NET_v6 (Pool): fd77:0:0:2::/64

2.4 MODERN (Dualstack, IKEv2)
- MODERN_VPN_NET_v4 (Pool): 10.77.32.0/20
- MODERN_VPN_NET_v6 (Pool): fd77:0:0:32::/64

3) BIND-/SCOPE-IMPLIKATION (Kurz)
- Alle internen Dienste binden an SERVICE_* (nicht an WAN, nicht an 0.0.0.0).
- VPN-Clients erreichen Dienste nur über erlaubte Scopes/Ports (nft input allowlists pro SERVICE-IP).
- DNAT DNS: Client DNS forced to SERVICE_DNS (10.77.0.1 / fd77:0:0:0::1) (B210 details)
- RESTRICTED forward drop: nur SERVICE_WEB (10.77.0.3 / fd77:0:0:0::3 :443/80) + SERVICE_DNS (10.77.0.1 / fd77:0:0:0::1 :53) + SERVICE_NTP (10.77.0.4 / fd77:0:0:0::4 :123/udp)
- Blockpage/Panel/diag liegen auf SERVICE_WEB (10.77.0.3 / fd77:0:0:0::3 :443/80), damit „DNS vs Web“ sauber getrennt ist.
- NTP liegt auf SERVICE_NTP (10.77.0.4), damit Zeitfix auch im Restricted Mode stabil bleibt.

4) TESTS
- Konsistenztest: In allen abhängigen Blöcken tauchen NETZE/Service-IPs exakt wie hier definiert auf.
- Service-Scope-Test: Kein Dienst lauscht auf WAN oder 0.0.0.0; alle lauschen nur auf SERVICE_*.
